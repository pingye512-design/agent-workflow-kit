# HANDOFF.md —— 断点续做交接单

> **为什么要这张纸**：任何 AI 都可能中途挂掉 —— 额度用完、限流、断网、进程被杀。
> 如果「做到哪了」只存在某个对话里，它一挂，进度就跟着蒸发，下一个人只能从头猜。
> **所以：进度必须落在硬盘上。**

最后更新：2026-10-19

---

## 三条规则

1. **一个任务一张卡**：开工前在 `tasks.json` 建卡；卡上必须写 `next_step`（下一句能直接执行的话）。
2. **小步落盘**：每完成一个「可验证的小步骤」就 commit + 更新卡片，不要攒着。攒着 = 一挂全丢。
3. **卡片只增不删**：做完把 `status` 改 `done` 并补 `note`，别删 —— 这是审计线索，也是「上次为什么这么改」的唯一答案。

```json
  "handoff_hint": "改动只在 web/ 下，接手的人 git pull 就能继续，不需要服务器权限",
  "note": ""
}
```

## 接手动作（照这个顺序走）

```bash
git pull
bash scripts/live.sh          # 生成最新现场快照
cat .agent-coordination/LIVE.md
bash scripts/lock.sh status   # 看锁在谁手上
```

1. 有 `doing` 卡 → 接着做，不要另起炉灶。
2. 有 `blocked` 卡 → 看解卡条件，条件不满足就跳过并说明。
3. 没有卡 → 建卡后再动手。

---

## 交付时必须写清

- **改了什么**：文件 + 行数变化 + 为什么。
- **怎么验证的**：命令 + 输出 + 时间戳。
- **怎么退**：回滚命令或备份时间点。
- **没做什么**：明确列出未覆盖的部分，不要让人误以为全都好了。
