# 01 · 为什么需要「现场快照」

## 问题

多个人（或几个 AI 工具）接同一个项目时，最常见的开场是：

> 「你先跟我讲一下这个项目是做什么的、上次做到哪了。」

这句话的代价很高：

- 讲一遍要 10–20 分钟，而且每次换工具都要重讲。
- 讲的人记不全，听的人理解偏，最后做出来的东西对不上。
- 真正的状态在对话里，对话一关就没了。

## 一个反直觉的结论

**手工维护的交接文档一定会过期。**

写的时候是对的，三小时后就骗人。不是态度问题，是结构问题：状态一直在变，而文档只在有人记得改的时候才变。

所以不要维护「状态文档」，要维护「生成状态文档的脚本」。

## 做法

`scripts/live.sh` 每次运行都会重新读取：

| 来源 | 得到什么 |
|---|---|
| `tasks.json` | 谁在做什么、卡在哪、下一步是什么 |
| `server-lock.json` | 服务器现在有没有人在动 |
| `git` | 当前分支、未提交改动、最近 5 次提交 |
| `curl $HEALTH_URL` | 线上接口现在通不通 |
| `df -h` | 磁盘还剩多少 |

输出到 `.agent-coordination/LIVE.md`，并在文件头写明「本文件自动生成，不要手改」。

## 使用约定

1. 任何 Agent 开工前先跑 `bash scripts/live.sh`，再读 `LIVE.md`。
2. 不允许手动编辑 `LIVE.md`。
3. `AGENTS.md` 里写死这条规则，换哪个 AI 工具都照做。

## 效果

- 新接手的 Agent 不需要问背景，读一页纸就能继续。
- 人也不用重复解释，只发一句需求。
- 状态永远是最新的，因为它不是「写」出来的，是「算」出来的。

## 一句话

> 把「现在什么状态」变成一条命令，而不是一段回忆。
