# 02 · 任务板与交接

## 为什么不用聊天记录当任务管理

聊天记录有三个致命问题：

1. **不可检索**：三天后想找「为什么这么改」，只能往上翻。
2. **不可交接**：关掉窗口，上下文就没了。
3. **不可并行**：两个 AI 同时改一个文件，谁也不知道。

任务板（`tasks.json`）把「工作」变成结构化数据，人和 AI 都能读写。

## 一张卡的最小字段

```json
{
  "id": "T-20261019-01",
  "owner": "cli-agent",
  "goal": "把每日汇总从本机搬到服务器",
  "files": ["scripts/patrol.sh"],
  "status": "doing",
  "next_step": "在服务器 enable 并观察两个周期"
}
```

| 字段 | 作用 | 常见错误 |
|---|---|---|
| `files` | 防冲突：两个卡占用同一文件时，后建卡的等 | 只写目录，不写具体文件 |
| `status` | `doing` / `blocked` / `done` | 做完了不改成 done，下一个人以为还在做 |
| `next_step` | 下一句能直接执行的话 | 写「继续优化」「跟进一下」 |
| `note` | 结果、失败原因、回滚方式 | 空着，等于没交付 |

## `next_step` 的标准

**不合格**：

- 「继续优化页面」
- 「跟进客户反馈」
- 「看看还有没有别的问题」

**合格**：

- 「在 `web/login.js` 的 catch 里按 `res.status` 分支两句文案」
- 「在服务器执行 `systemctl enable --now patrol.timer`，观察两个周期」
- 「给 `tests/test_api.py` 补 3 个用例：空参数、超长、非法金额」

判断标准：**接手的人读完这句话，不需要再问任何问题就能动手。**

## 交接的动作

```bash
bash scripts/handoff.sh
```

输出 `HANDOFF-latest.md`：任务状态、今天的提交、未提交改动、写锁状态、接手提示。

再配合 `git commit`，换台机器 `git pull` 就能续上。

## 卡片只增不删

做完把 `status` 改成 `done`，补上 `note`，**不要删**。

理由：三个月后有人问「这个规则为什么这么设计」，唯一能回答的就是那张卡和那次 commit。
